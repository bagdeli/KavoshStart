# Specs

Use a short Spec/plan only when complexity, coordination or an important unresolved decision warrants it (WK-5, DOC-1). For a selected Spec, use `specs/<issue>-<slug>/spec.md` when an Issue already exists, or a descriptive slug when it does not; `plan.md` describes the approach. Keep the existing work record when it is sufficient. Create GitHub sub-issues only for genuinely independent work with distinct ownership or acceptance; never maintain a parallel live tasks file. Templates: `specs/_template/`.
